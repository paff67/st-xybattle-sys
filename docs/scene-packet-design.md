# SillyTavern 本轮交锋场景包（2026-10-06）

## 使用边界

酒馆主模型已经能读取聊天、主角人设和世界书。战斗扩展只补充**独立裁定后、本轮已经发生的交锋事实**。主角功法只给名称与行动简述；敌方本轮实际招式给可观察表现、实际交互机理和结果。写作风格、剧情推进方式、写作指令与禁令留给后续主预设，本次不修改外部预设。

原方案有四个问题：固定“实质创伤/天地剧变”要求可能覆盖无伤结果；人物档案携带行动前状态；累计事件、人物视图和嵌套 JSON 重复；演示地点时辰进入正式剧情。本版从输出契约和注入投影两处移除这些来源。

## 包结构

类型仍为 `BATTLE_SCENE_PACKET`，负载 schema 为 `battle_scene_v3`。外层 `XY_BATTLE_PACKET v1` 标记保持不变；会话、分支、行动、版本等仅供宿主去重与过期检查。

以下是**结构示例**，不表示重新裁定用户原战斗：

```json
{
  "type": "BATTLE_SCENE_PACKET",
  "schema": "battle_scene_v3",
  "actionId": "example-action",
  "roundId": "example-round",
  "scope": { "chatId": "example-chat", "branchId": "example-branch" },
  "playerAction": {
    "action": "拂弦试探对手，建立弦势",
    "school": "叠浪玄潮诀",
    "technique": "弦势"
  },
  "exchange": {
    "playerResult": "弦势已建立，许妍取得先手",
    "opponents": [{
      "name": "厉沧海",
      "response": "保持站位，以剑势引开身前气流",
      "techniques": [{
        "name": "守势回流",
        "manifestation": "剑身微震，身前气流分成两股",
        "interaction": "仅发生局部偏流共振，未打断主角起势"
      }],
      "result": "双足稳立，未发生反噬"
    }],
    "environmentResult": "仅有局部气流偏转",
    "boundaries": [
      "未造成固定伤害、强制位移或破防",
      "未造成台面碎裂、积雪切断或大范围灵压爆发"
    ]
  }
}
```

- `playerAction.intent` 可选，表示用户意图，不能当作成功结果；结果在 `exchange.playerResult`。
- 每个敌人一条记录，未参与者说明保持状态。未用招时 `techniques=[]`，不猜测或填入所有已知能力。
- `manifestation` 描述本轮可见动作、武器/气流运动与作用范围；`interaction` 描述在本轮如何生效、受阻或失效。这里是裁定事实，不是正文 CoT 或写作要求。
- `boundaries` 是明确未发生的效果事实，不是泛用写作禁令。没有额外边界时为 `[]`。
- 公开招式名及功法名来自已确认 Registry；内部招式只保留公开表现，不自动泄露招名、原始完整规则和秘密参数。
- 不传 `playerVisibleContext`、人物常态档案、全部招式、资源表、全量语义状态、累计事件、地点时辰、`reason`、`descriptionRequirements`、`prohibitions`、`storyAiDirective` 或嵌套包。新版包不再并列重复 `summary/committedFacts/publicEvents`。

## 裁定到注入

1. 裁定请求保留完整内部战斗资料，并要求返回 `exchange`。新真实裁定缺失该结构时进入既有修复流程，修复仍失败则不提交。
2. 程序检查结构、对手覆盖、招式归属与注册情况，并把交锋内容纳入已有隐藏信息检查。状态、资源、因果操作仍使用原有提交校验。
3. 提交完成后，将敌方 ID 转成姓名、招式 ID 转成公开名称，组成唯一一份本轮事实负载。
4. 输入框和 `injectPrompts` 后备通道都调用同一白名单投影；原手写 prompt 留在酒馆输入中。正文 HTTP 路径也使用相同投影，不再把前一版正文/CoT 填回重写请求。
5. 主剧情模式注入后自动点击酒馆 `#send_but`，无需用户再补一条输入或手动按发送。发送前再次确认作用域、落盘版本、回执和输入框标记；先设置发送标记再点击，避免同步事件重复发送。原有手写内容与场景包一起发送。宿主忙碌/按钮不可用/标记丢失时提示失败，保留裁定，用户可点击“发送主剧情”重试；不后台无限重试。
6. 正文回写仍可保留在内部历史和开发审计中，但玩家战况卡、战史只接收裁定摘要与公开事件，不接收 narrative 字段。

程序能验证结构、引用和现有隐藏字符串匹配，**不能证明自然语言事实之间没有矛盾，也不能保证真实模型的公开机理描述质量**。提示词要求 exchange 与 summary、after、资源变更一致；无伤和轻微扰动是合法结论。真实模型输出仍需实机验收。

## 兼容与迁移

- 旧存档重写/注入只提取其本轮 `committedFacts` 并去重，不回填旧 `publicEvents`（该字段含累计历史），也不凭空补全旧回合敌人招式。
- 输入框已有同身份、同事实的旧标记时原位升级，前后用户文字保留；内容冲突则拒绝重复追加。不会篡改已经发出的聊天记录。
- 旧版默认裁定提示词按完整文本匹配自动迁移；自定义提示词保留，请求中始终追加新交锋输出契约。
- 草稿只在当前页面内、同聊天/分支/会话中保留。关闭/ESC/点击遮罩和标签切换不销毁表单；换作用域/会话清空。刷新浏览器不承诺恢复未提交输入。

## 验证

`tests/scene-packet.test.js` 覆盖无伤边界、过时状态排除、敌方招式归属、内部招式隐藏、旧包重写和提示词迁移。`tests/workbench-drafts.test.js` 编译实际 Vue 组件，通过 jsdom 事件验证关闭重开、标签切换、作用域隔离和正文 CoT 不进入战况/战史。宿主夹具分别覆盖输入框与一次性后备注入，并覆盖控制器提交→原生按钮自动发送→正常生成事件→正文回写，以及重复/忙碌/过期/跨聊天拦截。当前完整测试 127/127 通过。

以上属于代码验证；按用户要求不运行 Playwright，不等同于真实 SillyTavern/真实模型验收。
