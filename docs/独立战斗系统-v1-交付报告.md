# 独立战斗系统 v1 交付报告

日期：2026-10-04  
仓库：`paff67/st-xybattle-sys`（从空仓库基线建立）

## 已实现

- 独立入口：根 `index.js` 动态挂载 `src/index.js`，创建 `xybattle-v2-root`、可拖动悬浮按钮和独立横向工作台；没有调用旧“小手机”脚本、`ph-body` 或其设置。
- 独立设置：裁定/正文模式、endpoint、model、最大输出、温度、结构修复次数、自动正文和用户原 prompt 均在本扩展面板；API key 只存当前内存，设置落盘、导出和日志会删除凭据。
- 状态机：`idle/awaiting_player/judging/committed/narrating/awaiting_next/ended/rewrite`；每轮使用 `actionId/roundId/version`，重复 actionId 直接返回已提交记录；停止和重写有 AbortController/epoch，迟到响应不会覆盖 ended；中断恢复不会自动重发。
- 语义裁定：AI 返回 `before/after/reason/ruleRefs/publicEvents`，程序检查 before 与当前状态、字段作用域和已注册 ruleRefs；数值不使用全局固定扣费。持续效果和语义状态随 session 跨轮保存。
- 功法 registry：`schema/battle-technique.schema.json`、`sample-data/dielang-xuanchaojue.json`，含叠浪玄潮诀的弦势、叠潮、回弦、潮眼、颤弓·回潮、泛音·潮眼。界面折叠显示原始定义、本轮动态可用状态和实时触发状态。
- 可见性：AI 上下文保留敌方 hidden；`getPlayerView()` 和公开日志/导出移除 hidden、敌方资源和敌方功法。日志折叠显示 AI 已读摘要、玩家可见包、AI 原始响应、程序校验、提交记录、正文包和请求元数据；完整裁定 prompt 只发送给模型，不进入公开日志，避免把 hidden 上下文嵌在字符串中。
- 模型适配：生产路径为显式 OpenAI-compatible HTTP adapter，发送 system/user messages，裁定 user message 包含完整 context（actors、registry、prior facts）；正文 adapter 使用同类 messages 并保留原 prompt。无配置时使用保护适配器拒绝请求；Mock 需显式选择。
- 正文桥：生成 `BATTLE_SCENE_PACKET`，包含地点、时间、公开事件、已提交事实、描写要求、禁止复判和下一决策点。`src/host-adapter.js` 提供可选 TavernHelper `setExtensionPrompt`/message extra 收据接口。
- 存储：`BattleStorage` 使用独立命名空间并把 chat/branch 编入 key，拒绝作用域错写；支持导出、导入（仅同作用域）和恢复。

## 未验证与风险

- 尚未在目标 SillyTavern 实例上安装并实测 manifest 加载、悬浮窗拖动、TavernHelper 注入和真实主剧情生成；不能把真实主剧情闭环写成已完成。
- `src/host-adapter.js` 是显式适配接口：若宿主没有 TavernHelper 或消息写回 API，会保留场景包并记录 interface-only，不猜测成功。正式接入应在 `getChatMessages(include_swipes:true)`、`setChatMessages` 保留原 swipes 的前提下写入 `message.extra.battle_v2`，并在停止/pagehide 清理一次性 prompt。
- 当前样例 registry 只内置叠浪玄潮诀六法；其他功法、敌方规则和资源约束需要按 schema 导入并由宿主提供场景/角色快照。Mock 只验证协议和 UI，不证明任何真实战斗平衡。
- HTTP adapter 已有超时和 AbortSignal，但真实服务的 URL、鉴权头、结构化输出格式仍需在目标服务上做最小探测；不要把 API key 写入仓库或日志。

## 运行与迁移

1. 开发回归：`npm test`、`npm run lint`。
2. 离线 UI：加载扩展后在设置中选“离线 Mock 演示”，开始战斗、提交行动、查看折叠日志和导出。
3. 生产模型：在独立设置选择 OpenAI-compatible HTTP，填写 endpoint/model/key；先用自动正文关闭验证裁定，再启用正文 adapter。
4. 宿主桥接：实现 `BattleHostAdapter` 的 scope、receipt 和场景包注入，再对目标 SillyTavern 的消息分支和一次性 prompt 做实机证据测试；只有通过后才把接口标为已接通。
