# 权威功法与持久战场对象：第一版

## 使用入口

宿主模式重新读取人物时，程序把指定六法的权威版本加入本次候选上下文；不会替换正在进行的旧战局。主角只绑定明确列出的已修招式，人物确认页可展开“核对已掌握的功法与招式”逐项勾选。不能根据库里有功法、世界书启用状态或只有一个功法名称，就自动授予全部招式。

确认后，按钮仍从 Registry 与人物所有权交集生成。权威模板中的 conditional 且无程序谓词的招式可提交意图，显示“实际条件由裁定检查”；这不等于已满足施展条件。原有显式程序条件、不可用招式仍遵循旧可用性校验。

旧战局继续使用原快照。要测试新机制，停止旧战局并重新读取、核对和确认人物。未绑定权威招式的旧流程兼容原有语义效果；绑定后的新持续效果统一写入对象账本。不会把旧文本效果猜测转换成对象。

## 四层职责

1. `authoritative-rules.js`：恢复原文定义、绑定已修引用、校验版本与来源定义、生成每场规则快照及召回反例。主角候选的同名规则文本不覆盖模板，未注册的同门招式阻止确认。
2. `combat-ledger.js`：保存资源批次占用、持续效果、场地锚点、情报四类对象；瞬时攻击只留在回合结果。每个对象有来源招式、所属、可见性、状态和依赖。情报另有知情人物列表。
3. `battle-state.js`：在修复循环中试运行整个对象变更提案，校验成功后，与语义、资源及因果状态一起提交并落盘。非法提案不部分提交；行动快照包括对象账本和规则快照，消息删除可原样恢复。
4. `battle-adjudicator-prompt.js`：每轮从存档重建完整规则、16 条潜在联动、当前对象及被召回反例。定义正文仅发送一次；不依赖模型聊天历史记忆。该契约同时追加到自定义 system prompt 后，避免旧效果输出示例覆盖新约束。

## 人物绑定

主角补全允许输出 `learnedTechniqueRefs:[{registryId,techniqueIds,proficiency,evidence}]`。程序填入 version 和 contentSha256 并展开只读机制资料。对旧式明确命名的招式，仅在学校名、招式名都精确匹配时转为引用，仍须用户确认。

`proficiency` 和人物境界保留为实例资料，不改写功法原文。权威绑定主角可以没有数值资源表，使用定性占用；不能为了通过资料验证虚构 100 点真气、三层叠潮或固定五槽。敌人的构造规则保持原有明确档案流程。

## 变更提交协议

绑定权威功法后，裁定响应必须包含：

```json
{
  "combatChanges": {
    "baseRevision": 0,
    "operations": []
  }
}
```

所有操作包含唯一 operationId、type、简短 reason 及有效 ruleRefs。详细输出契约见 `COMBAT_LEDGER_CONTRACT`；首版支持：

| 操作 | 含义 | 程序约束 |
| --- | --- | --- |
| create | 创建跨行动事实 | 新编号、人物确实掌握来源招式、来源规则引用、有效的既有依赖 |
| update | 修改描述、位置、依赖；释放资源占用 | 只能改白名单字段；不能改归属、来源或复活终结对象 |
| retire | 中断、到期、消耗、销毁 | 已终结对象不能重复使用；依赖失效传递到下游，独立效果不受影响 |
| reclaim | 将散逸水元标记已回收 | 无活动占用、未销毁/回收，所属人物掌握气海回流或太一回澜，同时引用原对象与回流招式规则 |

同一批次沿用 resourceKey，不能重复新建同键资源。新对象按依赖顺序创建，禁止悬空依赖和循环依赖。每轮最多48项操作。同一行动重复提交同一提案幂等；同一行动换一份提案、旧 revision 提案均拒绝。

对象账本不推导不存在的数量，回收占用标记也不会自动增加数值资源。已有数值资源仍通过 resourceChanges 和资源边界校验。程序不能仅从两段不同的中文描述证明它们是同一份水元，模型语义一致性仍需验收。

状态默认不按现实时间或凭空给出的回合数自动衰减。到期、信息过时、控制中断由本轮提案明确提交依据；被销毁的依赖由程序立即传播失效。当前不支持把中断对象直接复活，重新建立须使用新对象编号。

## 反例召回

`content/authoritative-six-arts/negative-cases.json` 包含39条招式案例、16条联动案例。每条有短场景、错误裁定、纠正边界、来源引用及触发词。案例是人为编写的假设，不是新增能力规则，也不是当前战局事实。

- 招式引用/完整招式名称优先；识别短关键词后，可联动召回对应功法关系。
- 关键词召回限于主角已绑定功法，不能从敌方隐藏资料触发。
- 每轮最多4条，JSON序列化总长度最多2600字符，确定性排序；剩余案例继续保存在本场规则快照。
- 无关输入不注入案例。16条联动规则本身仍完整提供，未召回其反例不等于遗忘联动。
- 每场固定案例与联动快照；升级案例库不会悄悄改变进行中的战局，新场/新人物确认时加载新版本。

生成命令：`python -X utf8 scripts/build-negative-cases.py`。模板重建命令和来源验证命令见六法目录设计说明。案例主要用于降低已知语义误判，不能证明模型永远正确；不应以反例的错误文本作当前判定。

## 验证与边界

代码回归覆盖权威绑定、候选错误定义替换、未掌握招式拒绝、原文伪改拒绝、回收与占用、依赖传播、孤立效果保留、循环依赖、幂等与过期版本、事务拒绝及模型修复、提示词重建、私密对象隔离、落盘恢复、删除回滚和实际 Vue 勾选控件。

首版支持在自由动作文本里表达多招式联动，由模型按固定规则给出结果和一组对象变更；尚未实现多按钮编排行动图、完整的形式化命中/伤害求解器、对象操作快捷按钮或真实模型语义回归。代码通过不等于真实模型已通过55条案例，应在实机检查跳弓与多功法交互结果。
