# P3 日常事务执行器

2026-10-09。本次实现接入现有 P0/P1，沿用已可用的宿主战斗工作台入口。非战斗默认后台执行，不打开人物确认或工作台，也不要求人工确认结果。

## 提示词与模块

提示词唯一源码为 `src/event-daily-prompts.js`，版本 `daily-adjudication-v1`。采用一份通用协议与八份专项约束：修炼突破、炼丹、炼器、探查、疗伤、破阵、追踪/追逃、一般日常事务。普通交流、设定讨论、未执行计划及无风险例行动作直接放行，不为每句话增加判定。

通用协议要求：

- 先核对主体、目标、已掌握的方法、当前进度、资源、前提、环境与时间尺度。输入意图不证明能力或资源存在。
- 由 AI 依据原文机制和事实裁定，不引入 DC、随机骰点、分差或程序成功率。程序只校验引用、输出结构和资源一致性。
- 区分成功、部分完成、失败、受阻、仍在进行和核心资料不足；未知不能直接判失败，受阻不能产生凭空消耗。
- 长流程只推进本次合理阶段。不因失败默认炸炉、走火入魔，也不因主角身份保证成功。
- 正文只接收可见结果、实际代价与持续后果。依据摘要留在开发审计，不请求或保存逐步思维链。

宿主模式读取当前角色卡所选常驻底则并冻结原文；从当前能力库召回被资料提及的权威功法完整定义，沿用来源哈希检查。召回只解释机制，不授予能力。定义源 `branchKnown=false`，不能单独满足人物所有权、库存、伤势或当前状态的证据要求。仍需本轮 MVU/分支事实。独立开发 API 可通过 `readDailyDefinitions(snapshot)` 提供同类资料。

## 执行与事务

自动分流 → 按模块提取引用 → 核对引用和缺项 → AI 提案 → 程序校验 → P1 保存并服务器回读确认 → 一次性内部事实包 → 主 AI 正文。

非战斗收据为 `event_daily_commit_v1`；既有战斗收据保持 `event_combat_commit_v1`。战斗状态查找跳过日常收据。宿主战斗仍移交现有候选人物/确认/回合流程，战斗与日常混合请求暂不部分执行。非交战的独立 `battlefield` 操作仍未实现。

同一输入最多六个有向无环行动，按依赖顺序处理。后一个行动读取前序实际结果与更新后的资源余额。前置结果不是完全成功时，依赖行动标为未执行；独立行动可继续。模型异常、无效提案、资料不足或作用域变化时不提交前缀结果。重生成复用已提交结果，不再次调用裁定模型或重复消耗。

数值变化只接受已提取范围中的现有 MVU 数值路径，必须匹配 before，after 有限且非负，不允许重复路径、空变更或战界四字段。前一步变化后的值作为下一步 before。无数值依据时仅表达有依据的定性代价，不制造“100 灵力”等基线。

本次不直接写 MVU/ACU，也不增加其字段；事实包交给原有正文/变量流程处理。紧邻的上一日常事务有数值变化时，下一日常事务核对当前 MVU 是否与该结果对齐，不匹配则 `daily_projection_pending`。这不是完整 P4 对账：非数值效果、物品产出、上限与复杂资源守恒依赖模型语义和宿主投影；隔有其他叙事事务时不把历史余额永久锁死。不能将此版本描述为完整自动变量写回或资源回滚。

## 悬浮提示与取消

提示位于 ST 主界面右上方，显示“正在准备修炼突破判定”“正在进行追踪 / 追逃判定”等当前模块、处理阶段与经过秒数。默认不打开工作台；点击“查看详情”才打开日志页。

“取消判定”是本次事件的显式放行操作：

1. 中止后台请求，废弃候选结果；模型不响应 AbortSignal 时，迟到结果也不能提交。
2. 同一输入记为 `passed / user_skipped_adjudication`，不生成执行收据或注入裁定场景包。
3. 恢复原生主 AI 正文生成；正文完成后不再追加战斗观察请求或自动唤起战斗。
4. 重生成该输入继续沿用取消决定；编辑输入后才成为新的事件。

取消适用于分流、资料准备与裁定阶段。进入最终保存时按钮收起，避免把已提交结果当作未执行；保存失败仍须先恢复 P1 一致性，不能绕过保存错误放行。ST 自身“停止生成”、关闭事件入口、切换聊天/分支属于中止，不会自动续写。用户取消判定与宿主停止并发时，以宿主停止/作用域变化为准。

## 日志

“天道秘录”新增当前聊天最近 80 条事务，含输入身份、分支、模块、状态、阶段时间、准备证据、规则原文、依据摘要、可见结果、代价、后果、数值变化和正文绑定。完整收据仍保存在聊天消息/元数据。原始模型错误显示校验失败原因，不将无效输出标为已提交。

候选结果可能已经出现在处理审计中，但只有 P1 提交确认后才生效；保存待确认时明确显示“等待保存确认”。完整开发审计复制/导出包含事务记录；公开战报出口仍只导出现有战斗公开日志，不夹带日常准备资料。组件采用文本插值，不渲染模型生成 HTML。

本次本地验证：全量 `npm test` 279/279 通过；最后一次作用域提示修正后，协调器与 Vue 专项 47/47 通过；`npm run lint`、`npm run build` 和 `git diff --check` 通过。`dist` 与 `third-party/st-xybattle-sys` 的 bundle、执行器文件哈希一致。

这些测试使用可控模型响应及宿主夹具，不代表真实模型语义质量或 yiyu 浏览器验收。没有调用真实模型、部署远端或测试已有战斗判定效果。真实 ST 应重点检查：提示位置、取消后主 AI 是否正常续写、无裁定包残留、变量是否只投影一次、日志刷新/切换分支后的状态。
