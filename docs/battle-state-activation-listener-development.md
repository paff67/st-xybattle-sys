# 战斗状态激活监听器开发记录

日期：2026-10-09。

## 使用方式与边界

在“独立机枢”的“MVU 战斗状态监听”中启用“状态从其他有效值变为‘待裁定’时自动准备战斗”，保存后生效。开关默认关闭，独立于输入语义分流开关。

监听器只读取当前消息分支的 `世界.战界` 四字段。只有有效的其他战斗状态变为 `待裁定`，且消息、变量写入和请求身份均能确认，才提交战斗准备请求。字段缺失不等于“无”；初次打开已经待裁定的聊天、重复回调和切换旧 swipe 不自动触发。新生成的 swipe/重新生成使用实际父消息状态作为基线。

唤起复用已有候选人物与战前确认流程，不自动选择招式、执行第一回合、发送空输入或生成正文。同一活动战局可以恢复，不重复生成人物；冲突战局或无法确定身份时停止自动接管并保留诊断。

本功能不写回 MVU/ACU。观察记录和接管状态保存在扩展 `xy_event_v1.battleActivation` 元数据中，与旧存档兼容。取消会消费本次请求并拒绝迟到结果，不修改世界中的“待裁定”状态。刷新后的未确定准备记录转为需要上下文核实，不自动重跑模型；已确认接管的草稿可恢复。

## 实现位置

| 层 | 文件与职责 |
| --- | --- |
| 纯状态检测 | `src/battle-state-observer.js`：有效基线、真实更新轮次、分支指纹、状态边沿 |
| 宿主适配 | `src/host-mvu-observer.js`：原生生成窗口、MVU 信号配对、指定消息分支回读、远端落盘确认、能力发现及清理 |
| 统一接管 | `src/battle-entry-coordinator.js`：语义输入、正文交战观察和状态边沿共用去重、取消、恢复与接管记录 |
| 身份与保存 | `event-coordinator.js`、`event-state.js`、`event-store.js`、`event-lock.js`：消息身份、可选元数据、共享短锁、最新 revision 与写入前守卫 |
| 战斗业务 | `battle-controller.js`、`host-adapter.js`：触发消息的固定上下文、幂等准备、持久化确认和已有会话恢复 |
| 生命周期与界面 | `event-runtime.js`、`ui/mount.js`、`App.vue`、`SettingsPanel.vue`、`DeveloperPanel.vue`：独立开关、展示、取消与诊断 |

MVU 回调不等待模型或保存整个聊天。没有消息 ID 的信号必须结合捕获的生成请求、消息对象、当前 swipe、同一变量对象上的更新完成/写入前信号及远端保存数据核对；仅时间接近或正文相同不算身份依据。宿主添加的 MVU 展示包装允许规范化比较，其他正文编辑仍使观察失效。

读取最新存档、领取请求和提交准备结果使用共享短锁，模型请求在锁外执行。新输入、停止生成、编辑、切换聊天/swipe 会取消或作废旧请求，迟到结果不能覆盖当前战局。本机制不宣称跨设备恰好执行一次。

## yiyu 只读接口探查与剩余验收

在隔离的 yiyu 测试角色聊天中确认：角色载入后可发现 MVU；顶层没有全局 `eventOn`，因此适配支持宿主共享 `eventSource`；`VARIABLE_UPDATE_ENDED` 和 `BEFORE_MESSAGE_UPDATE` 事件名可读。对复制的数据调用解析接口，观察到更新完成事件的前后变量参数，聊天内容及输入框前后未改变，临时回调已清理。

该复制数据探查没有完成真实的“其他值→待裁定→保存→准备”流程，也没有证明完整的写入前回调、消息保存及额外模型分析时序。参考 MVU 源码用于适配事件与展示包装，但不视为已验证当前安装版本的全部写入行为。

仍需在隔离宿主中完成规划文档的真实验收：正文更新变量后的自动准备、额外变量分析、新 swipe/重新生成、取消与刷新恢复，以及与语义入口同时触发时只准备一次。本次没有推送 GitHub 或部署到 `me_sillytavern`，没有运行真实模型战斗。
