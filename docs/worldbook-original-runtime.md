# 世界书原文裁定接入（2026-10-08）

## 权威功法与法宝

本版以用户指定的 `E:\Downloads\自定义全能 .json` 为权威范本。文件 SHA-256：`20d8d8072738c3ef903032d5ee4e333c59410ab019e04a367c2c9cf7c94c09cf`。

导入 UID 9、14、15、16、17、18 的六部功法（40 项招式）与 UID 10、4 的沧弦潮音、潮痕行履（22 项能力）。没有导入家族和服饰条目。世界书原有 disable 标记仅保留为来源信息；是否拥有、是否启用仍由用户在战前选择。

`scripts/import-worldbook-abilities.mjs <文件路径>` 可重建 `content/worldbook-abilities/abilities.content.json`。按条目内的 cultivation_lore 名称识别，逐字保留 content（包括换行和结尾限制），记录世界书名、UID、文件与条目 SHA-256、段落字符区间。索引来自原文标题，未再编写一份替代规则。

新的人物准备使用该原文内容库；主角从 MVU 读取当前资料，用户手动激活功法、法宝与所用招式。世界书里提及其他功法，不自动授予它们；高境界描述不代表当前人物达到该境界。

确认人物后，原文随 Registry 快照保存。本场只保留已启用来源及参战人物生成的档案。每次裁定通过 `abilitySources` 发送选中条目的完整原文，Registry 发送 `sourceId/sourceRef/ruleRefs` 索引；原文不截断、不摘要，同一条原文只发送一次。角色档案中对应部分也改为请求时引用，避免重复传输。

缺少原文、散列不符、招式正文与引用区间不符时，开战、恢复或裁定请求会报错。已进行的旧战斗保持旧快照；使用新版必须结束旧战斗并重新准备、激活、确认。升级扩展不暗中更换既有战斗规则。

## 常驻底则配置

独立机枢新增“常驻底则 · 跟随角色卡”。读取世界书列表，选择世界书后勾选需要的 UID，再保存。可以跨世界书选择条目，同 UID 用世界书名区分。配置默认空，不根据 UID 猜测来源。

建议在相应世界书选取 `[25]` 与 `[420]～[423]`。功法法宝走上述按激活装载的原文通道；无需把整本“自定义全能”重复设置成常驻规则。

选择存放在当前酒馆账号的 `extensionSettings.xybattleCoreRules[角色卡avatar]`，宿主保存设置。同一卡不同聊天复用，不按可能重名的显示名绑定；重命名角色卡文件后需要重新配置。群聊目前不提供此单卡配置。

战前读取所选原文，冻结为本场 `coreRules`，每条带书名、UID、SHA-256 和可引用 `id`。条目不存在、重复或内容为空时停止准备。读取直接使用宿主世界书接口，每次请求最长 15 秒，不读取旧缓存作为新场景规则。

战斗或人物准备期间，界面与控制器同时拒绝修改配置。空闲时保存更改会撤销未确认草稿，要求重新准备加载原文。战斗中世界书被外部编辑不影响已冻结内容。

裁定请求保留用户原 system prompt，另加一条独立 system 消息承载 `coreRules`；结构修复请求同样携带底则。返回接口不需要回传原文，只需在 `ruleRefs` 引用输入实际给出的 id。原文和来源元信息随战斗保存与恢复，不写入 MVU。

## 验证边界

本地回归覆盖原文逐字一致与单次传输、八项内容库、手动激活、旧战斗不升级、缺失/篡改拒绝、跨书同 UID、跨聊天同卡设置、同名卡隔离、战斗锁定、战前冻结、保存恢复与实际 HTTP 请求体。

本次没有调用付费真实模型，也没有自动发送主剧情。原文信息已接入不等于 AI 语义裁定验收通过；定性状态输出仍参见 `dynamic-combat-contracts.md`。用户保存的候选人物与裁定提示词没有被本次改造重写。
