# 酒馆账号配置

配置使用 TavernHelper 的 extension 作用域 `xybattleConfig`，包含四类 API 参数与各自凭据、提示词和入口开关。当前实现基于 ST 1.17.0 / 酒馆助手 4.11.0 的真实接口记录。启动等待 ST 导出的 settingsReady 和 helper；失败只显示重试入口，不用浏览器旧配置替代宿主配置。

首次无配置时显示默认表单，不自动保存。旧浏览器配置按来源列出，明确点击“迁入酒馆配置”后才提交。原本地数据保留，宿主模式不再写本地 settings/credentials。离线测试仍可显式使用独立控制器；离线挂载需指定 offline: true。

保存前校验完整配置，检查草稿 writeId、当前内存和服务器版本；战斗、人物与非战斗事务共用配置排他锁。参数、提示词和凭据作为同一 envelope 提交。已有 API Key 在补丁中缺省时保留，空字符串明确清除。

“已提交”只代表酒馆内存接收成功；延迟保存可能尚未发送。“核对服务器保存”通过 POST /api/settings/get 核对同一 writeId 和完整内容，成功才显示“已确认服务器保存”。保存失败或未确认时不盲目回写旧配置。入口启用失败单独显示。

自定义提示词原文保留，不按旧模板内容猜测替换，不 trim 后回写。空白自定义提示词不能保存；恢复默认只修改草稿，保存后生效。builtin 使用模板 ID 与版本；不自动升级旧自定义文本。

密钥在 ST 用户设置中以普通字符串保存，不提供额外加密。普通配置导出移除凭据并脱敏，导入缺失凭据时保留现有密钥。战斗存档导入不采用其中的 settings。内容库、窗口位置、战斗快照和角色卡底则继续使用各自已有存储。

其他设备使用同一实例同一账号并刷新后才能读取服务器版本；无实时推送。宿主保存整份用户设置，revision / writeId 不构成跨设备原子锁。避免同时编辑；切换设备前刷新。页面主动重新加载会询问是否丢弃草稿。

实现与阶段 A 接口探针验证不等于完整发布验收。阶段 D 的实际配置双浏览器往返、手机、账号隔离、真实凭据请求和重启分别记录；未完成前不宣称全部跨设备验收完成。迁移 envelope 保留 pending 元数据，服务器确认由同一 writeId 的读回结果表达；尚未提供自动删除旧本地配置操作。
